# 前三阶段研究数据修订稿：数据库专业候选能力体系 v1

本目录是供研究者审查的候选修订，不是已经验证或最终定稿的能力体系。代码基线为main `d01b26e33665b8f89018dd47597501e5547896f2`（已合并PR #6）。旧Excel、旧图谱、网页、部署配置和教学映射/评价结果均保持不变。本次不开发网页、不采集新招聘、不新增逐条招聘原文核验任务。

## 文件与运行

九份可编辑Excel在 [output](output/)；方法及待审问题见 [研究方法与修订报告](研究方法与修订报告.md)。从仓库根目录执行：

```bash
python -m pip install -r research_revision/database_competencies_v1/requirements.txt
python research_revision/database_competencies_v1/build.py
python -m unittest discover -s research_revision/database_competencies_v1 -p 'test_*.py' -v
```

只依赖openpyxl 3.1.5；本次在Python 3.12.14执行。脚本自动扫描现有工作簿，按实际工作表/字段唯一识别输入，不假定原文件所在目录。保留文件、工作表、字段、Excel行号和原引文；指纹与输入快照不符会停止，不能静默用新数据替换证据。外部输入更新需同时审阅规则和快照。

默认只重建本目录output下的修订工作簿，不覆盖旧成果。可用`--output /tmp/审查副本`输出副本；拒绝写入本修订目录以外的仓库目录。Excel内容级复跑一致（不承诺ZIP容器字节时间戳一致）。

`rules.json`是逐条阅读摘要后由AI辅助拟定、待研究者审核的拆分/归并/相关性/能力与关系规则，并非专家结论或训练所得模型。脚本不调用LLM或招聘网站；重跑按同一规则执行。原仓库85个文件的Git blob哈希保存在`input_snapshot.json`中；构建校验原Excel，测试同时校验全部85文件未改动。

## 先读这些边界

“直接”指现有**摘要**明确出现技术对象和动作，不是招聘原文明示、已核验岗位或专家确认。原表A/B/C质量等级保留，但不作为已经核验的证明；招聘原文明示证据数为0。

第一阶段只检查样本结构与质量；第二阶段提取片段并归并任务；第三阶段先提出具体技术叶能力，再归纳类别/领域。没有预设数量，也没有套用旧5—14—34。多表连接、完整性约束、建表等不能因课程需要或用户示例而加入核心。

核心5项均有直接摘要支持：数据库查询与数据提取、SQL清洗、数据库备份、数据库恢复、数据库查询性能优化。行为表现与初步评价指标是研究拟定，不是招聘原文要求，不制定教学任务、评分或学生达成度。6条R编码只是证据不足线索，不授予核心三级编码，不计入核心数量，也不补齐其行为评价。

179片段中157来自职责、22来自任职；同一岗位/上下文可按不同活动维度拆分，多条片段不是独立岗位需求。核对准确数量请以processing_summary为准。所有岗位仍为待核验候选，疑似重复未删；旧109条疑似关系不自动继承。新版是独立审查稿，不会更新当前平台或改写1/18/14/1课程支撑结论。
