# 旅游行业岗位需求研究：第一阶段

本项目使用 Python + openpyxl 检查候选招聘样本、提取典型工作任务，并形成三级职业能力候选指标。**50 条均为待核验候选岗位，不能当成 50 条已核验独立招聘，也不能据此声称具有全国代表性。** 本阶段未构建课程图谱，未使用或补写《数据库原理及应用》课程标准。

## 分类与分析方法

保留原直接/关联分类，另给出可审核的建议分类与摘要依据：摘要涉及 SQL、数据库、清洗、建模、数据治理、数据提取或指标口径时，建议直接相关；涉及业务分析、数据使用或信息系统但数据库核心任务不清楚时，建议关联。建议与原分类不一致时提示复核，不覆盖原值。这是与数据库课程主题的初步相关性判断，不是课程标准符合性结论。

任务以职责摘要按分号、句号、换行及中文逗号分段，任务文本保留原摘要内容，编码为 `T-岗位ID-序号`。每条保留岗位 ID、证据文本、证据字段、原表单元格位置、链接、原分类、初评等级与本轮待核验状态。本轮 79 条任务全部标记“摘要证据”。部分摘要含复合任务或名词性表达，当前保留其语义粒度，后续须依原文细分，不能视为经过现场工作分析确认的原子任务。任务编码在同一输入及顺序下稳定；修改职责摘要或分句顺序后应重新审核编码。

能力按处理对象与业务目的自下而上归纳为 26 项三级、15 项二级、5 项一级能力。一级包括数据资源处理、业务数据分析、信息系统保障、业务系统建设、业务协作与研究。三级是具体可观察的能力，二级聚合相近任务目的，一级概括业务功能；不是难度等级。归纳规则与行为指标位于 `scripts/phase1.py` 的 `RULES`，在指标体系中同时输出触发规则和支撑任务 ID。

要求性质以关系行为单位区分：

- **明确要求（摘要明示）**：任职摘要有相应正向能力表述；仍不是已核验的原文明示。
- **优先要求（摘要明示）**：对应局部短句明确出现“优先”。例如“熟练SQL，Python/R优先”不能把 SQL 标成优先。
- **研究推断（由职责任务归纳）**：任务支持某能力，但任职摘要没有相应正向表述。不把“未明确SQL”“待核验”转为明确要求，也不直接使用原表“能力标签”作为强证据。

全部任务到能力的**映射关系和层级组织均为研究推断**，与任职摘要是否明确要求某项能力分别记录。一个任务可映射多项能力。规则是便于复核的初步内容分析，不具备完整语义理解，否定、优先范围、复合任务及跨领域同词均需专家复核。未命中规则的任务会保留并列入未映射页，不自动填充能力；本批 79 条均有映射，共 188 条关系。支撑岗位频次包含疑似重复，不代表独立招聘次数或权重。

例如 JOB001 的“搭建会员标签与画像体系”形成任务 `T-JOB001-01`，归纳至“组织会员标签与画像”；其任职摘要未明示标签能力，故标研究推断。JOB002 的“SQL/Python分析并输出报告”支持使用 SQL、业务分析和成果表达；SQL 的任职摘要证据单独保存，性质为摘要明示要求。两例均待原文核验。
