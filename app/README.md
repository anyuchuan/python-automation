# 《数据库原理及应用》课程能力图谱与教学优化分析平台

以旅游行业候选岗位需求为依据，以课程能力体系为核心，以教学内容映射和教学优化分析为应用目标。只读展示前三阶段研究成果，不生成新的岗位、能力、知识点或支撑关系。

## 本地启动

支持Python 3.11和3.12，Cloud部署基线为3.12。仓库根目录执行：

```bash
python -m venv .venv
source .venv/bin/activate
# Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python -m streamlit run app/main.py
```

浏览器访问终端地址，通常为 http://localhost:8501 。需要完整仓库中的 `phase3/output/`、`app/input_snapshot.json` 和 `app/frontend/index.html`，不能只复制main.py。

Community Cloud设置：仓库 `anyuchuan/python-automation`，分支 `main`（本PR经人工审核合并后），入口 `app/main.py`，Advanced settings选择 **Python 3.12**。已有3.14实例需要重新部署才能更换解释器。详见[部署说明](部署说明.md)。

## 六个模块

| 模块 | 主要用途 |
| --- | --- |
| 课程能力图谱（默认首页） | 默认折叠能力树，树/网络切换，共享右侧详情与跨模块快捷入口 |
| 岗位能力需求分析 | 按能力检索候选岗位、摘要任务、证据文本与已有关系；不计算正式需求频次 |
| 能力—教学内容映射 | 34×8交互矩阵，点击单元查看项目层判断、原理由、知识点、实践任务、引文与物理页码 |
| 课程能力支撑评价 | 34项能力整体判断、技术行为边界，另列272项目单元统计 |
| 课程教学优化 | 分开呈现研究发现、建议分类、依据和待核实事项，保持来源可追溯 |
| 研究依据与数据管理 | 数据快照、证据口径、隔离关系目录、当前风险规则的数据导出 |

## 第一次使用

1. 首页先显示5项一级能力。点击 **＋/−** 逐级展开/折叠，或用顶部按钮展开至二级、全部展开、全部折叠。
2. 点击名称选中能力，右侧查看编码、定义/行为、父编码、研究状态与相关任务。源数据未单列的“能力定义”显示“暂无记录”；可观察工作行为另列，不改称招聘原文。
3. 输入编码或名称后回车可定位首个匹配；多结果可再选择并点击“定位所选能力”。定位只展开祖先，不强制展开所有分支。
4. 选中三级能力后切换 **网络关系**，该能力保持为中心。点击网络能力后，可点击图内 **定位到能力树** 回树选中并展开其祖先。
5. 网络点击节点查看属性，点击连线查看原关系证据；可滚轮/按钮缩放、拖动画布。点击“展开所选节点”以该节点为新中心查询已有邻域，不创建关系。右侧能力详情保持当前能力；选中非能力节点时，其属性在图下另列。
6. 网络“节点、关系与证据筛选”支持类型、关系类型、证据状态组、1–3跳邻域和20–100节点上限。当前子图CSV与绘制结果一致；截断会显示提示。
7. 右侧快捷入口进入映射/评价，继续使用当前三级能力。矩阵中点击任意单元，右侧展示该能力与项目；也可用编号和项目下拉选择。行筛选是能力整体等级，单元颜色是项目层等级，二者不混用。

所有按钮和树节点可用Tab/Enter操作。完整矩阵可横向滚动；详情有独立滚动区域，适合普通笔记本使用。

## 数据版本与统计口径

自动只读加载第三阶段修订版的四份Excel：知识图谱节点表、知识图谱关系表、职业能力课程匹配矩阵、课程能力覆盖与缺口分析。路径基于 `__file__`，不依赖当前工作目录。启动校验文件指纹、节点/端点、等级与34×8单元；禁止回退至旧版5项直接支撑。

| 口径 | 数量与含义 |
| --- | --- |
| 全量来源 | 50候选岗位、79摘要任务、34三级能力、8教学项目；314原始节点、864候选关系、另60隔离关系 |
| 职业能力树 | 5一级＋14二级＋34三级＝53项N编码，48条父子关系 |
| 能力整体判断，分母34 | 直接1、部分18、未见明确14、待审核1 |
| 项目单元判断，分母272 | 直接1、部分24、未见明确230、待审核17 |
| 未见支撑项建议分类，分母14 | 潜在改进4、其他课程可能承担5、旅游业务背景4、证据不足1 |
| 默认风险规则候选视图 | 259节点/450关系；默认显示仍不代表人工确认 |
| 主动开启全部探索 | 314节点/924关系，含60隔离关系；不升级证据状态 |

“当前筛选”“当前子图”和“当前展示规则关联”计数均是局部口径，不替代全量统计。最新main旧首页不能复现4岗位/2任务/2能力为全量数值；缺少现场部署快照，不能确认具体成因。此版全量计数独立计算并测试，不使用局部图作为分母。

原表52条“建议能力层级包含”中4条属于无招聘证据课程建议S编码；职业能力树只纳入53项N编码及48条关系，未删除S记录。完整来源与哈希见数据管理页。

## 研究边界

候选岗位、摘要、研究推断、课程文本支撑、待审核和隔离状态保持原值。109条历史疑似关系不默认确认，也不新增招聘核验任务或将核验作为后续前置条件。默认隐藏隔离及高风险推断，必须先开“研究探索模式”再主动开启各类显示。

课程文本支撑不是学生能力达成或经核验行业需求覆盖。未见明确支撑不是课程绝对不涉及；建议不是已采纳方案、课标新增内容或专家结论。矩阵“项目审阅范围”原文仅说明查阅范围，不冒充正向支撑证据。历史遮挡候选不作已确认实训依据。

图例以绿色实线、黄色虚线、紫色虚线、红色虚线区分直接、部分、研究推断/待审核和风险探索。未见明确支撑只标能力/单元状态，不虚构正向支撑边。项目内实践学时已计入项目总学时，不直接叠加32学时实践口径。

## 技术与性能

Streamlit + 原生HTML/SVG双向组件，无新增依赖、CDN、Node构建、图数据库或外部服务。`app/frontend/index.html`通过Streamlit组件协议回传选择和定位；Python端验证ID并维护跨视图状态。数据加载缓存保留PR #5行为，文件变化才重新解析；启动不运行研究流水线或PDF解析。

树只含53项，默认仅5项；网络只传当前局部图，默认上限60节点，矩阵仅272单元。当前Linux测试服务器运行后RSS约216MiB，仅作环境观察，不等于8GB Mac实机性能认证。
