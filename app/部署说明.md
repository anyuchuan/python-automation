## 依赖配置及兼容边界

- Cloud先搜索入口目录：本项目使用 `app/requirements.txt`；根目录 `requirements.txt` 通过 `-r app/requirements.txt` 引用同一套依赖，避免本地与云端版本漂移，仍包含研究脚本所需的openpyxl。
- 只有四个直接依赖：Streamlit 1.50.0、pandas 2.2.3、openpyxl 3.1.5、Altair 5.5.0。不安装PDF解析库、Playwright、PyVis、Neo4j或编译器。
- `--only-binary=:all:` 要求使用wheel；不支持的解释器会尽早明确失败，避免云端尝试耗时源码编译。这不自动更换Python版本；管理员仍须在平台设置3.12。
- pandas 2.2.3没有CPython 3.14可用Linux wheel。针对3.14的pip二进制查询以及uv二进制依赖解析均失败，构成现有依赖栈的具体兼容风险。没有在3.14解释器内执行完整源码构建，不能把它表述为已证明3.14永远无法运行本应用。
- 当前“Resolved 39 packages in 561ms”只表示解析结束，不表示包已全部下载、安装和应用已启动。后续可能等待下载、构建或平台资源。仅凭这段日志，不能确认卡住的唯一原因。
- 不添加其他包管理器配置来竞争依赖文件，也不依赖仓库文件控制Cloud解释器。CI的Python版本仅控制GitHub Actions，不能替代Cloud设置。

## 启动过程与数据路径

`app/main.py` 和 `app/data.py` 均以 `Path(__file__).resolve().parents[1]` 定位仓库根目录，路径不依赖当前工作目录。只读加载已提交的：

1. `phase3/output/知识图谱节点表.xlsx`
2. `phase3/output/知识图谱关系表.xlsx`
3. `phase3/output/职业能力课程匹配矩阵.xlsx`
4. `phase3/output/课程能力覆盖与缺口分析.xlsx`

同时读取 `app/input_snapshot.json` 验证来源指纹。数据加载在 `st.cache_data` 内，文件mtime/大小和快照变化才重新解析；普通页面切换不会重跑Excel读取。首次只读加载实测约0.26秒（当前测试环境），不是云端耗时承诺。启动不解析PDF、不抓招聘、不调用研究流水线，只有进入图谱页面才生成当前局部SVG。

首次加载时Cloud日志应出现 `Course graph: loading existing Excel on Python ...` 和 `Course graph data ready: ... in ...s`。这些日志可区分“依赖尚未完成”与“应用已进入数据加载”。加载提示只在缓存未命中时出现；缓存命中不重复打印加载日志。

## 本地复现

使用Python 3.12创建独立虚拟环境，从仓库根目录执行：

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check
python app/check_deployment.py
python -m unittest discover -s app/tests -v
python -m streamlit run app/main.py --browser.gatherUsageStats=false
```

诊断脚本只读输出Python/依赖版本、输入文件、图谱计数、支撑等级与加载秒数，不修改研究文件。应读取314节点、864候选关系、60隔离关系、34项能力等级1/18/14/1；这些计数不是已经核验的事实或能力达成结论。

## 常见问题

| 日志或表现 | 检查与处理 |
| --- | --- |
| 长时间停在 Processing dependencies / Resolved | 保存完整后续日志；确认实际Python为3.12、选中的requirements及部署分支；检查是否下载/构建中。一次重启不能消除版本不兼容；3.14实例须更换解释器部署。仍停滞且无新日志时检查Streamlit服务状态及平台构建资源，向平台支持提交时间、版本和脱敏日志。 |
| `pandas==2.2.3 has no usable wheels` / `No matching distribution` | 本PR启用了尽早失败。确认Cloud Advanced settings选择3.12，而非给仓库加runtime.txt；不要直接删掉版本约束或禁用二进制限制来掩盖问题。 |
| `ModuleNotFoundError: openpyxl/altair` | 确认部署当前已审核分支和 `app/main.py`；检查安装日志使用app目录依赖。根目录转发提供同样安装集合。 |
| 数据文件不存在 / 来源指纹不同 | 确认完整仓库及四份修订Excel在同一分支，文件名区分大小写。不要用修订前档案替代，也不要禁用指纹校验；合法数据更新须审阅快照。 |
| 有健康检查但页面仍失败 | 健康接口只代表服务器存活。还应实际打开首页、图谱探索及证据详情，查看Python异常和 `data ready` 日志。 |
| `missing ScriptRunContext` 仅出现在自动化测试 | AppTest/裸脚本环境可能打印此提示；测试是否通过以退出码及断言为准，不能据此认定Cloud启动失败。 |

## 阶段五组件与兼容性

默认首页为能力树，六模块仍使用同一入口。必须提交并部署 `app/frontend/index.html`、`app/visuals.py`、`app/platform_model.py` 和 `app/controller.py`；缺少frontend目录会导致双向组件无法加载。组件无CDN、无需Node、额外Secrets或新增依赖，通过Streamlit自身组件协议通信。Python 3.11与3.12均已完成依赖检查、只读加载和30项自动化测试，CI覆盖两种版本。默认树先显示5项，完整层级为53项；不要把局部网络计数当作全量。

部署后除健康检查，还需确认：默认5项一级能力可展开、搜索N113后能切换网络、网络选中能力可回树定位、272单元矩阵点击能显示课程引文。当前环境没有Cloud控制台，未实际重新部署，Cloud最终运行结果仍需管理员验证。
