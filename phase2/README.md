# 第二阶段：三级职业能力体系审核与优化

本目录独立保存第二阶段代码、规则和成果；根目录招聘样本、第一阶段 `output/`、`scripts/`、`tests/` 及 README 均保持不变。默认输入为已合并 PR #1 的 main 快照，来源提交和各文件 Git blob 见 `input_snapshot.json`。

## 运行

从仓库根目录运行，Python 3.10+，依赖沿用根目录 requirements.txt 中的 openpyxl 3.1.5：

```bash
python -m pip install -r requirements.txt
python phase2/review.py
python -m unittest discover -s phase2 -p 'test_*.py' -v
```

自定义位置：

```bash
python phase2/review.py --input-root /path/to/repository --output /path/to/phase2_results
```

程序仅离线读取文件，不访问招聘网页，不更改原始岗位或第一阶段结果。新旧编码及具体支持规则集中于 `rules.json`，输出位置默认为 `phase2/output/`。结构、岗位/任务外键或原编码覆盖异常时停止处理，不静默修复原数据。实际数量与预期不同会在报告说明；输入与锁定快照不同时报告文件差异，不能把新输入继续称为原main快照。新增原能力编码时需先人工更新规则。

程序禁止输出到第一阶段 `output/`、`scripts/` 和 `tests/`，运行前后核对输入 SHA256。它会覆盖所选第二阶段目录的同名文件，**人工已填写的审核版本须先另存备份**。相同输入和规则产生相同单元格、关系和报告；Excel ZIP 元数据可能变化，不要求二进制相同。

## 证据、计数与审核规则

1. 招聘原文明示本批为0；A/B/C原初评级别不代表已核验。原任务仅摘要，全部岗位待核验。
2. 岗位摘要支持仅表示任务摘要出现较具体动作或对象。研究推断保留为待判断关系，不纳入摘要支持计数；拆分分项无支持时明确不建议迁移，保留原轨迹。
3. 全部层级组织、任务到能力关系、评价行为和A/B/C课程适配均为AI辅助研究判断，均待人工审核。摘要明确/优先要求字段只透传第一阶段结果，未声称为招聘方原文明示。
4. 仅摘要支持关系以岗位ID、任务ID取集合计数；合并及上位节点取并集，不能相加叶节点频次。统计含疑似重复，不是独立招聘需求频次。课程建议和研究推断不得计为摘要支持；已核验原文岗位数始终为0。
5. A数据库课程核心相关、B数据库课程延伸相关、C旅游行业背景相关，不代表课程标准覆盖。上位含多类子项时暂归B，应按三级逐项审核。
6. SQL是逐关系技术限定；一般提取或分析不能推成SQL。备份不能推出恢复，应用权限不能推出数据库授权，模型设计不能推出ER设计，数据更新不能推出明确DML语法。
7. 规则只复核原关系映射范围，并非全文语义识别或所有可能关系的穷举。宽泛词识别和正则筛查仅生成审核建议；命中较具体关键词仍不等于专家认可，未命中也不证明职业需求不存在。
8. 保留原任务ID，不改写79条任务的粒度；复合任务单独列问题。审核结论和审核人均为空，不模拟人工确认。本阶段未构建最终课程图谱、未增加课程知识点，也未引用未提供的课程标准。
