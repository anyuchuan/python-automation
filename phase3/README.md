## 运行与测试

Python 3.10+，从仓库根目录执行：

```bash
python -m pip install -r phase3/requirements.txt
python phase3/build.py
python -m unittest discover -s phase3 -p 'test_*.py' -v
```

可指定输入根目录和独立输出位置：

```bash
python phase3/build.py --input-root /path/to/repository --output /path/to/phase3_results
```

PDF自动遍历发现，按正文中的课程名称识别，不根据文件名或路径推断。多个候选时停止，待人工选择；必要时可用 `--pdf` 指定已确认的仓库PDF。本次自动发现唯一文件《课标0913.pdf》，13个物理页。程序离线运行，不重新核验招聘网页。

第一、二阶段文件必须齐全；缺少第二阶段能力体系、对照或审核数据时停止，不回退到第一阶段26项能力。源文件与main快照不一致时停止并报告差异，需先人工重新审阅及更新快照。输出默认写入 `phase3/output/`，禁止写入前两阶段输出和代码目录。

重复运行会覆盖第三阶段同名成果；已填写的人工审核版本须另存。相同输入与研究方案保证相同单元格、统计和报告，Excel压缩元数据可能变化，不要求二进制相同。

## PDF可见性与学时口径

**第13页的32学时实训表和考核标题位于后绘制的白色覆盖矩形下。** 文本层虽能提取，实际页面不可见。程序利用文本、绘制顺序和覆盖矩形检测这一情况，保留候选摘录、页码与单元格坐标，但不把遮挡内容视为已确认的发布正文。未删除白色覆盖，也未改写PDF。可见性核对图随成果保存。

8个可见教学项目共64学时，含理论32与实践32；课堂实操要求属于项目内部，不能再次叠加。遮挡文本层还列实训一/二/三10/12/10学时及总计32，但其有效可见版本及与64学时的关系未明确，不能相加为96，也不能断言是同一分配。

原文“INERT INTO”保留，不自动纠正为INSERT INTO。考核标题被遮挡，未提取到可确认的考核组成、比例或评分细则；可见的课堂操作检查只作为教学反馈要求保存，不冒充正式考核方案。

## 结构化与匹配方法

- 课程结构：14条目标、8项目、8条项目学生要求、37条知识条目（34项项目内容、2项目标提及、1项思政提及）、8条可见项目内实操要求及3条遮挡表候选。11条实操记录不是11个独立实训项目，未增加学时。
- 引文校验：97条摘录逐一对照PDF物理页及坐标；10条涉及遮挡，仅作候选。原文字词及提取换行保留，校验时仅去除空白。不同条目可能引用同一原文，不是97个独立来源。
- `course_specs.json` 是本次PDF的研究结构化方案，知识名称与粒度由研究者赋予，不是官方编码；引用必须存在于该PDF。
- `matching_plan.json` 对34项能力逐项比较工作动作、对象、工作产出与课程实践。它是可审核的研究判断，不是关键词自动定级，也不是预先人工批准。
- 多对多矩阵54行，按唯一能力汇总为：直接支撑5项、部分支撑14项、未见明确支撑14项、待人工审核1项。全部匹配仍待人工审核。
- 直接/部分判断只使用可见原文及项目内实操，未利用遮挡32学时表确认实训支撑。目标层可无项目/实训ID，未见支撑行无正向引文和虚构占位节点。
- E-R模型不是岗位分析/预测模型，数据库GUI不是业务看板，SQL统计不是完整经营分析，课堂运行查询不是软件功能测试。权限/DCL目标与思政审计提及不能自动等于具体授权/安全审计实训。
